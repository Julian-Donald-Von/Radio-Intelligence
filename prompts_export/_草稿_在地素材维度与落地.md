# 在地素材 · 维度头脑风暴 + 落地方案（草稿，未落提示词）

> 用户的判断：**城市天气不是"不用"，而是要用"真的、可核查的"东西替代** ——
> 并且要超出"景点/美食"，把**城市概览（森林覆盖面积、水系、城市历史…）**这类也纳入，
> 因为这些**正是联网检索该去取的东西**。

---

## 一、先定一条设计原则（决定了后面所有取舍）

**在地素材不是"装饰"，它必须挂在"与这首歌的关系"上。**
否则无论多真实、多具体，都是旅游手册 —— 而旅游手册正是 v2 要杀掉的"套话"。

⇒ 所以维度表分两层：**① 可检索的在地事实**（原料）→ **② 桥接规则**（什么时候用哪一类）。

---

## 二、可检索的在地事实（六个域）

| 域 | 维度 | 具体能问出什么 | 与音乐的接口 |
|---|---|---|---|
| **A 自然/地理** | **水系** | 穿城河、湖、运河、海岸、潮汐；"城市有没有一条从中间过的水" | 流动感／漂泊／慢歌的节拍 |
| | **森林覆盖率 / 绿化率** | **可查的具体百分比**（注意口径：全市 or 建成区、哪一年） | 自然系／民谣／"绿"的听感 |
| | 地形与海拔 | 平原／盆地／丘陵／山城（坡度＝步态） | 节奏的"坡度感" |
| | 气候类型 | 温带季风／海洋性／大陆性；年降水与湿度区间 | 干／潮的体感 |
| | 纬度与日照 | 天黑时刻、冬夏昼长差（高纬极端） | 都市夜／漫长下午 |
| | 主导植被/树种 | 梧桐／银杏／椰林／松；花期与落叶期 | 物候＝季节锚点 |
| **B 城市史/结构** | **建城年代与名字变迁** | 何时建、曾叫什么（⚠ 见风险 1） | 年代感／怀旧 |
| | **曾经的支柱产业** | 纺织／煤矿／港口／铁路／电子 | **工业、后朋、民谣的"城市记忆"最强接口** |
| | 铁路/港口/渡口 | 汽笛、轮渡、编组站的声景 | 声音锚点（可直接写） |

## 三、桥接规则（**这才是让素材"不空"的关键**）

| 歌的特征 | 该去取哪一类在地素材 |
|---|---|
| 慢、冷、内省 | 水系（缓慢流动）、雾、老工业区、夜里收摊的街 |
| 燥、失真、有攻击性 | 工业史、高架/地铁、拆迁、市集的吵 |
| 怀旧、年代感 | 建城史、老厂/老影院、方言、老树种 |
| 自然、民谣、原声 | 森林覆盖率、山/湖、物候（落叶/花期） |
| 都市夜、city pop | 日照时刻、霓虹与营业时间、河风 |

## 四、可检索性分级（决定"能不能真用"，不是"想不想用"）

| 级 | 内容 | 说明 |
|---|---|---|
| **A 好查** | 水系、森林覆盖率、建城年代、产业结构史、方言 | 静态百科，检索一次可长期复用 |
| **B 中等** | 本地 livehouse、本地乐队、树种物候 | 要挑 query |
| **C 实时** | 今天天气、日落时刻、供暖季起止 | 需专门的实时源，**别用模型"记得的"** |
| **D 禁止** | "这座城市的音乐性格""市民情绪" | **不可核查 ⇒ 一律不许写** |

## 五、⚠️ 风险清单（这一节最重要）

1. **★★ 地名/城市史是"望文生义"的**新**高危区** —— 你现在要模型多谈城市，
   而城市名**同样"共形不共义"**：
   - 「**长春**」≠ 长久的春天　·「**石家庄**」≠ 石头的家
   - 「**无锡**」≠ 没有锡（**历史上恰恰产锡**）·「**驻马店**」「**宝鸡**」…
   ⇒ 必须新增一条**与"专名纪律"同源**的规则：
   **地名与城市史只许引用检索到的事实，禁止从字面推演。**
   （你那张题库第 1 档的精神，直接扩到地名上。）
2. **数字必须带口径** —— "森林覆盖率 45%" 要能说清是全市/建成区、哪一年，
   否则就是另一种编造。
3. **景点/美食最容易塌成旅游手册** —— 必须过"与歌同频"这关，否则就是套话。
4. **物候/供暖是月份敏感的** —— 1 月写"梧桐落叶"就是错。
5. **在地素材有"注意力预算"** —— 50 字里只能有一个在地物象（与之前的草稿一致）。

## 六、落地方案（App 侧，对应"联网检索所必须"）

### 1. 检索 query 从 1 条扩到 3 条
```
① 歌曲侧（现有）：{artist} {title} 歌曲 创作背景 专辑 评价
② 在地侧（新）  ：{city} 城市 水系 森林覆盖率 历史 产业
                  {city} {当前季节/月份} 物候 天气 特点
③ 关系侧（转场）：{artist} {next_artist} 合作 同厂牌 翻唱
```

### 2. **检索结果结构化**（关键）
把结果整理成"已检索到的在地事实"字段块，**查到才列、列了才准用**：
```
【已检索到的在地事实（仅这些可用；未列出的不许写）】
城市：长春 | 水系：____ | 森林覆盖率：__%（口径） | 建城：____
支柱产业史：____ | 方言：____ | 本季物候：____ | 本地音乐场景：____
```
这一块与刚改的「联网补全」规则**天然咬合**：没检索到的字段模型不许自己补。

### 3. 预算与节流
- `CTX_BUDGET` 1400 → **2500**（要多放一整个在地域）
- ★ **在地资料按城市做日缓存**（同一城市一天只查一次，复用到当天每一首）
  ⇒ 这是省钱关键，也让"长春"重复出现时**有真内容可写**，而不是只会复读地名。

## 七、提示词段落草稿（接上一份《D 级转形规则》）

> **在地素材只许"转形"引用，不许"报地名"**
>
> 允许用到的在地内容**只有两类**：
> 1. **可核查的在地事实**：水系 / 森林覆盖率 / 建城年代 / 支柱产业史 / 方言 / 本季物候 /
>    本地音乐场景（livehouse、老唱片店、本地乐队）。
> 2. **感官转写**：把上述事实或当下的天气，转成**体感与意象**（潮、白汽、河风、灯箱、汽笛）。
>
> **严禁**：
> - 直接写城市名、天气词、温度数字（「深夜长春」「今天晴」「18 度」）；
> - **从地名或城市名的字面推演含义**（「长春」不是"长久的春天"，「无锡」不是"没有锡"）；
> - 说城市"音乐性格/气质"这类**不可核查**的判断；
> - 引用**没有出现在资料里**的在地事实（查不到就整段不用在地）。
>
> **上限**：整条口播最多 **1 个**在地物象，且必须与这首歌同频（歌冷选冷角落，歌旧选旧东西）。
